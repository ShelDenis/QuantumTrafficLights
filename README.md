# QuantumTrafficLights

Проект содержит экспериментальную постановку задачи оптимизации фазовых
смещений светофоров через QAOA. Исходный файл `main.py` строит Ising-
гамильтониан для выбранных маршрутов и оптимизирует параметры QAOA через
PennyLane.

## Что добавлено

В отдельной реализации `qaoa_openqasm.py` добавлен генератор OpenQASM 2.0 и
Python-обвязка для гибридного запуска:

- строится та же бинарная модель фазовых смещений: один кубит соответствует
  одному светофору из используемых маршрутов;
- слагаемые гамильтониана `Z` и `ZZ` объединяются по одинаковым кубитам, чтобы
  уменьшить глубину схемы;
- QAOA-слой экспортируется в OpenQASM 2.0 через базисные операции
  `h`, `rz`, `rx`, `cx` и `measure`;
- двухкубитное слагаемое `exp(-i gamma * c * ZiZj)` раскладывается как
  `cx`, `rz(2 * gamma * c)`, `cx`;
- добавлен гибридный цикл оптимизации SPSA, который подходит для шумных
  backend-ов, потому что оценивает градиент только двумя измерительными
  запусками на итерацию;
- добавлен локальный `statevector`-backend без внешних зависимостей для быстрой
  проверки;
- добавлена опциональная поддержка Qiskit Aer через `--backend qiskit-aer`;
- после запуска сохраняются OpenQASM-файл и JSON с отображением
  `светофор -> кубит` и коэффициентами Ising-модели.

## Почему не весь алгоритм перенесен в OpenQASM

OpenQASM 2.0 описывает квантовую схему, но не выполняет классическую часть
гибридного алгоритма. Поэтому в QASM переносится только параметризованная QAOA-
схема с уже выбранными значениями `gamma` и `beta`.

Классический Python-код остается ответственным за:

- загрузку дорожного графа и маршрутов;
- построение коэффициентов Ising-гамильтониана;
- запуск схемы на backend-е;
- расчет энергии по результатам измерений;
- обновление параметров `gamma` и `beta`;
- интерпретацию лучшего битового состояния как фазовых смещений светофоров.

Такая архитектура соответствует реальному QAOA-процессу: квантовый backend
оценивает стоимость текущих параметров, а классический оптимизатор выбирает
следующие параметры.

## Размер текущей задачи

Для маршрутов из `routes_for_quantum.py` используется 12 уникальных светофоров,
поэтому схема требует 12 кубитов. После объединения одинаковых слагаемых
получается:

- 12 однокубитных `Z`-слагаемых;
- 12 двухкубитных `ZZ`-слагаемых;
- при глубине `p = 4` примерно 96 `cx` до транспиляции и учета топологии
  конкретного квантового устройства.

Это намного компактнее, чем прямой экспорт всех повторяющихся слагаемых из
PennyLane-модели.

## Быстрый запуск

Сгенерировать OpenQASM 2.0 без оптимизации, используя начальные параметры из
исходного `main.py`:

```bash
python qaoa_openqasm.py --no-optimize
```

Запустить короткую локальную гибридную оптимизацию на встроенном
`statevector`-backend-е:

```bash
python qaoa_openqasm.py --iterations 20 --shots 2048
```

Использовать Qiskit Aer, если установлены `qiskit` и `qiskit-aer`:

```bash
python qaoa_openqasm.py --backend qiskit-aer --iterations 20 --shots 2048
```

Переопределить глубину и начальные параметры:

```bash
python qaoa_openqasm.py --depth 2 --gamma 0.5,0.3 --beta 0.2,0.4
```

По умолчанию создаются файлы:

- `qaoa_traffic_lights.qasm` - схема OpenQASM 2.0;
- `qaoa_ising_model.json` - коэффициенты модели и соответствие узлов кубитам.

## Запуск на реальном backend-е

Файл `qaoa_traffic_lights.qasm` совместим с OpenQASM 2.0 и может быть передан в
инструментарий провайдера, который принимает QASM 2.0 или умеет импортировать
его в собственный формат схемы.

Для backend-ов, работающих через Qiskit, в коде выделен класс `QiskitBackend`.
Он принимает готовый backend-объект и запускает сгенерированную QASM-схему с
заданным числом shots. CLI использует локальный `AerSimulator`, если выбран
`--backend qiskit-aer`; для облачного устройства нужно подключить провайдера в
отдельном Python-скрипте и передать backend-объект в `QiskitBackend`.

## Ограничения

- Модель оптимизирует только бинарное фазовое смещение: фаза `0` или фаза `1`.
- Длительность цикла, порядок фаз и многозначные смещения пока не кодируются.
- Качество результата на реальном устройстве зависит от шума, числа shots и
  транспиляции под топологию backend-а.
- `statevector`-backend нужен для проверки и разработки; он не моделирует шум
  реального квантового компьютера.
